# 数据安全表单（Data safety）填写对照

Play 管理中心 → **应用内容 → 数据安全**。下表是按当前代码实际行为给出的建议答案，请逐项核对后再提交。
**表单必须与真实行为一致，虚假申报会导致应用下架。**

## 一、总体问题

| 问题 | 建议答案 | 依据 |
| --- | --- | --- |
| 你的应用是否会收集或共享任何必填的用户数据类型？ | **是** | 可选的云端备份会上传用户名、密码哈希与加密后的备份文件 |
| 所有收集到的用户数据在传输过程中是否都经过加密？ | **是** | 仅 HTTPS，`network_security_config.xml` 全局禁用明文；OkHttp 未配置任何明文降级 |
| 你是否提供了一种让用户请求删除其数据的方式？ | **是** | 应用内「设置 → 删除数据」入口，本机密码库与云端账号一并删除（有云端账号时只需输入密码，用户名已保存在本机）；隐私政策页面同时给出邮件申请渠道 |
| 你是否承诺遵守 Play 家庭政策？ | **否** | 本应用不面向儿童，最低目标受众为 13 岁以上 |
| 是否已独立验证你的安全做法？ | **否** | 未做第三方安全审计，如实选择 |

## 二、收集的数据类型

> 关键概念：**"收集"指数据离开设备**。本应用的本地密码库不上传，因此**不需要**申报密码条目本身；
> 只有「云端备份」这条链路涉及数据传输。

### 1. 个人信息 → 用户 ID（User IDs）

| 字段 | 选择 |
| --- | --- |
| 是否收集 | **是** |
| 是否共享 | **否** |
| 是否必须（不可跳过） | **否** — 用户可以不使用云端备份 |
| 用途 | **应用功能**（账号识别与备份归属） |
| 是否用于个性化 | 否 |
| 是否加密传输 | 是 |
| 是否可请求删除 | 是 |

### 2. 个人信息 → 其他信息（Other info）

用于申报「加密后的密码库备份文件」这一项。

| 字段 | 选择 |
| --- | --- |
| 是否收集 | **是** |
| 是否共享 | **否** |
| 是否必须 | **否** — 仅在用户主动开启云端备份时 |
| 用途 | **应用功能**（跨设备备份与恢复） |
| 是否加密传输 | 是 |
| 是否可请求删除 | 是 |

> 说明：备份内容在设备端完成 AES 加密后才上传，服务端不持有解密密钥。
> 若你在 Play 表单的说明栏可以补充文字，建议写明这一点；但**仍然如实勾选"收集"**，避免审核判定为漏报。

### 3. 其余类型：全部选择"不收集"

| 类型 | 结论 | 说明 |
| --- | --- | --- |
| 位置（精确/大致） | 不收集 | 未申请任何定位权限 |
| 个人详细信息（姓名、邮箱、地址、电话、证件） | 不收集 | 注册仅需一个用户名 |
| 财务信息 / 支付信息 | 不收集 | 无内购、无支付 |
| 健康与健身 | 不收集 | — |
| 消息（短信、邮件、聊天） | 不收集 | 未申请短信/通讯录权限 |
| 照片和视频 | 不收集 | 相机画面仅用于本地解码二维码，不落盘、不上传 |
| 音频文件 | 不收集 | — |
| 文件与文档 | 不收集 | 无文件读写权限 |
| 日历 | 不收集 | — |
| 联系人 | 不收集 | — |
| 应用活动（页面浏览、搜索记录、应用内交互） | 不收集 | 无任何埋点 SDK |
| 网页浏览记录 | 不收集 | 无 WebView、无浏览历史读取 |
| 应用信息与性能（崩溃日志、诊断、耗电） | 不收集 | 未接入 Crashlytics / Bugly 等 |
| 设备或其他 ID | 不收集 | 未读取 IMEI / Android ID / 广告 ID |

## 三、安全做法

| 问题 | 建议答案 |
| --- | --- |
| 数据是否加密传输 | **是** |
| 是否遵循 Play 的"数据安全"最佳实践（最小化收集） | **是** |
| 用户能否请求删除数据 | **是**（应用内 + 邮件双通道） |

- [ ] 与 `AndroidManifest.xml` 中声明的权限一致（INTERNET / ACCESS_NETWORK_STATE / CAMERA）
- [ ] 若后续新增统计 SDK、崩溃上报、广告，**必须回来更新本表单**，否则视为违规
- [ ] 若后续关闭云端备份功能，可把「用户 ID」「其他信息」改为"不收集"，并同步修改隐私政策
